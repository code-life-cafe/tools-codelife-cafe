# WebMCP上位3件の実装・検証

対象: Mermaid、YAML/JSON/TOML、個人情報マスキング。Risk Class R3。

## 受け入れ条件と実装

- 55件を対象に、既存のmanifest・レガシー定義・ページでの実登録を照合。既存12件対応、未対応43件。全順位と理由は `webmcp-priorities-2026-10-12.md` に記録。
- 上位3件の既存処理を `defineMcpTool` の単一ソース定義で公開し、registryと各ページのuseEffectへ接続。生成manifestは10定義から14定義へ増加。レガシーtax/unix-timeは既存のまま。
- Mermaidは修復・SVG生成、形式変換は6方向・整形・キーソート、マスキングは対象6種・全文字/一部伏字・2種の伏字を提供。
- UIの既定値とWebMCPの既定値は独立。WebMCPのマスキングは共有用途を想定し全文字伏字を既定にする。AIへ既に渡した情報の漏えいを取り消す機能ではない。
- 修復・形式変換・マスキングの入力は100000文字、SVG描画は5000文字上限。入力データのfetch・保存・ログ・計測を追加していない。既存のSVGレンダラーはstrictモード。ブラウザ非対応では登録がno-op。

## 独立レビュー修正（1周目）

入力上限と省略時既定値が公開スキーマに出ていない指摘を受け、3件のtextにmaxLengthを宣言し、共通生成器でmaxLength/defaultを出力するよう修正した。実行時の検査・既定値は変更せず、クライアントへ明示する。既存ツールのdefaultも同じ宣言からmanifestへ反映。生成器と3件のスキーマの回帰テストを追加。

GitHub CIの初回lint/型チェック/build/全unitは成功。ローカルでのみ発生したONNX課題とは区別する。初回E2EとSecurity Reviewの結果はGitHub PRの最新状態を参照。修正後headのCI・独立レビューを改めて確認してからMergeする。


## 独立レビュー修正（2周目）

JSON SchemaのmaxLengthはUnicodeコードポイント単位だが、実行時がUTF-16 code unitを数えていた。共通の上限検査を導入し、生成器validator・3件のhandler・Mermaidの修復/描画前段を一致させた。3件それぞれでastral文字を含む100000文字の受理と超過拒否の回帰テストを追加。BMP文字の上限は維持する。処理を停止できる早期判定とし、文字配列全体の生成は行わない。


## Security Review修正（3周目）

YAML alias増幅とメール検出の二乗時間走査を修正。WebMCP形式変換だけ安全モードを適用し、YAML aliasを解析時に拒否。ソート/シリアライズ前に深さ50・ノード10000・展開文字量を制限し、出力4MiB上限を適用する。通常UIのalias変換は維持。メール検出は@起点の線形走査へ置換し、従来regexとの検出・位置一致を確認。入力100000文字を5秒の隔離プロセス上限内で処理するテストを追加。単純な有界走査にしたため、新規Worker・依存・状態管理は追加していない。


## 人間承認による追加修正（2026-10-12 14:45 JST）

3周上限の例外としてMermaid描画対策・再レビュー・デプロイ・実機テストまでの続行承認を受領。未公開APIを修復（repair_mermaid_code、100000文字）と小型SVG描画（render_mermaid_svg、5000文字）に分離し、スキーマから異なる上限を明示。描画は50文・50エッジ、出力1MiBに限定し、設定上書き・並列リンク展開・外部画像/HTML描画を拒否。通常UIの描画上限は変更しない。同期DOM描画はPromiseタイマーで強制停止できないため、キャンセル可能と偽らず、処理量を事前に制限する。6247メッセージの再現入力と小型図の境界を検証する。


追加のtimeline 1行展開の指摘に対し、WebMCP描画だけflowchart/graph/sequenceDiagramへ限定。通常UI/修復の図種は維持する。各文200文字とMarkdownラベル制限、htmlLabels=falseも適用し、長いラベルによるDOM展開を抑える。1000イベントのtimelineは描画器に入る前に拒否する回帰を追加。
