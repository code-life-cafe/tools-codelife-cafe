## 実装範囲と順序

1. 承認後、最新mainから作業する。現在のローカルmainは保存済みorigin/mainより149コミット遅れている。既存の未コミット変更を保持し、別checkoutで現行実装・既存PR・重複機能を再確認する。
2. PDF.jsによる1ページ描画と既存pdf-libによる再保存の小さな検証を行う。日本語フォント、回転ページ、Worker、同一オリジンの静的アセット配信、ブラウザのメモリ上限を確認する。依存の版・ライセンス・既知脆弱性をこの段階で確定する。
3. PDF圧縮を実装・検証する。
4. 同じ描画経路を使ってPDF→JPG/PNG変換を実装・検証する。
5. Claude MakerによるDraft PR、Codexの独立レビュー、最新headの必須CIへ進む。MergeとDeployは別の人間承認を残す。

Risk Classは全体R3。新規ツール・依存追加に加え、信頼できないPDFを解析するため追加リスクレビューを実施する。Constitution、権限、CI・Deploy設定は対象外。

## PDF圧縮の仕様案

- 初回は1ファイル、50MiB以下・100ページ以下。画素数上限は1ページ16メガピクセル。実機検証で下げる場合は計画へ記録する。上限を緩める場合は再判断する。
- 標準は構造の再保存による最適化。文字を画像化せず、縮まらない場合は元ファイルを保持して「これ以上小さくできませんでした」と表示する。必ず縮む、無劣化で大幅削減できるとは表示しない。
- スキャン向けの画像化圧縮は、利用者が明示選択した場合だけ実行する。文字選択、検索、リンク、注釈、フォーム等が失われること、画質が変わることを選択時に表示する。これはOCRを保持する方式ではない。
- 画像化は72/96/144dpiとJPEG品質を選択できる。ページの見た目の向き・縦横比・ページ数・並び順を維持する。
- 署名付き・フォーム付きPDFは初回範囲から除外し、日本語で理由を示す。検出方法を検証し、検出不能なケースを対応済みとしない。
- 暗号化・破損PDFは日本語エラーで停止。パスワード解除は追加しない。
- 前後サイズ・削減率・ページ数を表示し、結果が元より大きい場合は小さい結果として案内しない。
- プレビュー、処理の進捗、キャンセル、結果保存を提供する。元ファイルは上書きしない。

## PDF→画像の仕様案

- 1ファイル、50MiB以下・100ページ以下。ページ範囲を選択し、JPGまたはPNG、72/96/144dpiで変換する。
- ページの回転・寸法・透過背景の取り扱いを明示する。JPEGは白背景。1ページ16メガピクセルを超える出力は拒否する。
- 出力画像の合計保持容量は200MiBまで。超える前に停止し、変換済み画像と未変換の先頭ページを示す。保存後にページ範囲を続きへ切り替えて変換できる。これは端末のメモリ不足を避ける実装上の制限で、入力の100ページ上限とは別に説明する。
- 複数ページは個別保存を初回仕様とする。ZIP一括保存は依存や機能を増やすため含めない。
- 連番ファイル名、プレビュー、進捗、キャンセルを用意する。PDF内部の埋め込み画像抽出とは別機能として説明する。

## 受け入れ条件と検証

- スキャンPDFで容量削減を実測し、文字PDF・画像PDFを分けて削減率、画質、所要時間を報告する。全PDFに同じ削減率を約束しない。
- 日本語、縦横ページ混在、90/180/270度回転、空入力、破損、暗号化、サイズ・ページ・画素数上限、キャンセル、縮まらないケースを検証する。
- 出力PDFのページ数と寸法、出力画像の寸法を独立に照合する。署名・フォームの拒否と文字保持の標準モードを検証する。
- 入力ファイル、抽出情報、結果画像を通信・ログ・localStorage・共有URLへ保存しない。保持するのは形式やdpi等の設定のみ。外部送信を遮断したE2Eだけで本番の通信安全性を証明せず、通常の配信状態でネットワークを確認する。
- 既存の日本語UIと共通コンポーネントを使用し、PC/モバイル・キーボード・フォーカス・状態通知を検証する。
- UIモックを目視確認してから適用。依存は遅延ロードし、トップページへの初期bundle増加を調べる。
- npm run lint、npm run test:unit、対象E2E、npm run build、型確認を実行し、既存PDFツールの回帰も確認する。E2Eはtests/e2e/fixtures/base.ts経由。
- Draft PR共有時は最新コミットと検証結果、含めなかった既存変更を記録。Merge判断には最新headの必須CI成功を使用する。

## 後続候補

- PDFテキスト抽出はAIへ渡す資料の準備用途に適するが、需要の成長率は未確認。上記のPDF描画経路が安定してから別計画とする。
- 日本語画像OCRは需要が確認できたが、2026年の検索人気度は減少。モデル配信・認識精度・端末負荷を伴うので初回に含めない。
- Office/HTML→MarkdownはAI向け文書整理の成長仮説として調査を続ける。Excel貼り付け→Markdown表は既存AI表データプロンプトと重複するため、XLSX直接読込・複数シート・単独md出力の差分に限定して評価する。
