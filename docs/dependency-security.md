# 依存脆弱性の運用

PRを止めるのは、比較元から新規・悪化した依存脆弱性。既存分も監査するが、無関係な修正のマージを停止する理由にはしない。全重大度を対象とし、ビルド依存も含める。

`node scripts/security-audit.mjs <比較元の完全SHA>` を実行する。PRでは最新baseを含むmerge commit、デプロイでは直前の正常デプロイSHAと比較する。比較元と対象に同じnpmとオプションを使用し、双方を同一ジョブで現在のレジストリ情報で監査する。レジストリは可変で原子的なDBスナップショットではないため、不自然な差分はレポートを確認する。

アドバイザリURL・パッケージ・lockfile内の配置・依存元への経路・解決バージョン・integrity・dev/optional区分で同一性を判断し、重大度増加も検出する。バージョン変更後も同じ脆弱性が残る場合は保守的に新規として停止する。依存元のバージョン更新だけで対象の脆弱な依存・経路が不変なら、既存分として扱う。件数の増減だけでは判定しない。アプリの利用経路・露出変更は依存監査だけでは判定できないため、独立Code/Security Reviewで確認する。

結果はActionsのSummaryと14日保持のartifactに記録する。既存分は修正担当・優先度・対応期限を定め、Dependabot通知と全件レポートを用いて継続対応する。脆弱性が既存であることは安全性の証明ではない。

通信障害、監査結果の形式異常、lockfile欠損、比較元不明は失敗にする。正常デプロイ履歴がない環境は自動的に空のbaselineやHEADを使用しない。初回の比較元は人間が別途設定方針を決める。

既存の必須lint/e2e、型・build・unitの成功と最新headの独立レビューは引き続き必須。admin/bypassでマージしない。
